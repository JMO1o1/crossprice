# crossprice

Cross-validated option pricing: three independent methods that must agree, and a harness that records
exactly where and why they stop agreeing.

> **Status:** the pricing core, cross-validation harness, implied-volatility solver and an offline SPX
> snapshot/smile analysis are implemented and tested. The agreement table below is generated by one
> command from committed code. The formal write-up (`docs/RESULTS.md`) is in progress.

### How to read it

- **What is compared with what.** European rows are judged against the Black–Scholes–Merton closed form.
  American rows are judged against a 6400-step tree of the *same* implementation, so they are a
  resolution self-consistency check, not an independent benchmark; BSM appears in those rows only as
  `unsupported`. Arithmetic Asian rows have no exact reference: the discrete geometric closed form is used
  as the AM–GM bound (lower for calls, upper for puts), never as the arithmetic price. Geometric Asian
  Monte Carlo is judged against its exact closed form with a z-score.
- **Grid.** 72 European contracts (S=100; K ∈ {80, 100, 120}; T ∈ {0.25, 1, 2}; σ ∈ {0.10, 0.30};
  (r, q) ∈ {(0.05, 0), (0.01, 0.03)}; call and put) × three methods; 24 American contracts (σ=0.2;
  T ∈ {0.25, 1}; (r, q) ∈ {(0.05, 0), (0.02, 0.05)}); 6 discrete Asians (12 monitoring dates); and 17
  named stress cases — expiry, one day to expiry, zero and very low volatility, deep ITM/OTM, negative
  rate, negative carry, negative dividend, five-year σ=1, a coarse tree that must reject its probability,
  a Monte Carlo sample with no positive payoff, and an American call at a negative rate.
- **The large relative errors are real and are reported, not clipped.** `max_abs_rel_error` for
  `mc_plain` (5.67) is a put with reference price 6.0e-6: 65 536 paths produce a handful of payoffs, the
  absolute error is 3.4e-5, and the row passes on the absolute term of its criterion. Relative error is
  the wrong yardstick when the reference is a fraction of a cent; the table shows both.
- **The five `degenerate` grid rows are two mechanisms.** Three are puts with reference ≈ 1e-6 to 6e-6
  where no path finished in the money (SE = 0, price 0; a zero-width interval, not certainty). Two are
  short-dated, low-volatility deep-ITM calls whose payoff was linear in the control variate on every
  sampled path: the controlled estimator's SE collapses to roundoff (3e-17) and its residual error
  (−1e-6, −6e-6) is the unsampled region. Both are logged with their mechanism rather than scored.
- **Family-level check.** With 166 stochastic rows the number of 95% intervals covering the reference
  should look like Binomial(166, 0.95); 158 does, and the z-scores have mean −0.09 and SD 0.96. The
  per-row threshold 4.04 is a Bonferroni budget: the probability that *any* correct row in a table of
  187 declared stochastic rows is flagged by chance is held at 1%, instead of letting each row carry its
  own 5% (or 0.1%) false-alarm rate. Individual 95% intervals are expected to miss about 5% of the
  time, and they do.

## What this is

- **Analytic** — Black–Scholes–Merton closed form with continuous dividend yield, plus analytic Greeks.
- **Binomial** — Cox–Ross–Rubinstein tree, European and American (early exercise).
- **Monte Carlo** — risk-neutral GBM simulation; every price ships with a standard error and a 95% CI;
  antithetic and control-variate variance reduction with the *measured* reduction factor.
- **Asian options** — discrete arithmetic-average Monte Carlo, an exact geometric-average reference,
  and an independent-pilot geometric control; monitoring excludes time zero and includes expiry.
- **Cross-validation harness** — prices the grids and stress cases above by every applicable method,
  judges each row against a stated reference with criteria fixed in advance, and logs rejections,
  degenerate samples and unsupported pairs instead of hiding them.
- **Implied volatility** — safeguarded Newton on analytic vega with SciPy Brent fallback;
  typed results record the method, iteration count, residual and explicit boundary/failure status.
- **Observed SPX smile** — a dated CBOE snapshot, per-quote cleaning and inversion audit, ATM-parity
  carry, source-IV comparison, bid/ask ranges and explicit rate/dividend sensitivities.

This is a pricing and numerical-methods project. Monte Carlo intervals quantify sampling error only;
they do not include model error or the difference between discrete and continuous Asian monitoring.

## Core API

Import deterministic benchmarks from `crossprice.analytic` (`bsm_price`, `bsm_greeks`,
`geometric_asian_price`), trees from `crossprice.binomial` (`crr_price`, `american=True` for early
exercise), and simulation from `crossprice.montecarlo` (`mc_price`, `asian_mc_price`).
All use `(spot, strike, tau, rate, vol, div=0.0, kind="call")` before method-specific keywords.
Analytic BSM inputs broadcast; tree and simulation contracts are scalar.

Monte Carlo requires `seed=` and returns `MCResult`, never a float. Inspect `price`, `se`, `ci`,
and `ci_status` together. `antithetic=True` uses pair-based standard errors;
`control_variate=True` uses an independent pilot. `variance_reduction` accounts for main and pilot
path cost and is a measured diagnostic, not a guaranteed improvement. Read function docstrings for
limit conventions, invalid-grid behavior, count restrictions and the degenerate-sample warning.

The harness lives in `crossprice.crossvalidate`: `run_agreement(cases, config)` returns the typed
table (`AgreementRun.table`, columns in `COLUMNS`), `default_cases()` / `stress_cases()` build the
case list, `crr_convergence()` / `mc_convergence()` return the plotted data, and `main()` is the
command above (also installed as the `crossprice-crossvalidate` script). Pass `--quick` for a coarse
smoke run with its own scaled tolerances; it is not the reported table. `crossvalidate` needs pandas and
matplotlib (`uv sync --group dev` or the `plots` extra).

### Implied volatility

`crossprice.implied_vol.implied_vol(spot, strike, tau, rate, price, div=0.0, kind="call")`
replaces the forward API's `vol` input with the target `price`. Its frozen `IVResult` carries `vol`,
`iterations`, `method`, `price_residual` (repriced minus target) and `status`. Consume `vol` only after
checking `status == "converged"`. Out-of-bounds prices raise; the lower bound reports `vol=0` and
`lower_bound`, the upper bound reports no finite root, and expiry reports unidentified volatility.
An observed rounded lower-bound price cannot rule out small positive volatility.

The default guess combines the forward-ATM Brenner-Subrahmanyam time-value approximation with the
BSM inflection point. Newton must stay bracketed and meet both the price (`1e-10` currency units) and
volatility-step (`1e-12` decimal vol) tolerances. Brent uses `xtol=1e-12` and four float64 epsilons of
relative tolerance. A shared 128-iteration budget and an explicit volatility cap of 16 prevent
unbounded search; exhaustion and excessive final residuals are recorded, not relabelled convergence.
Bracket-search evaluations are excluded from the reported iteration count.

Reproduce the inversion evidence with `uv run pytest tests/test_implied_vol.py -q -s`.
The fixed seed tests 256 well-conditioned contracts per kind, including signed rates and dividends,
against a predeclared `5e-10` absolute volatility tolerance. Separate tests exercise forced zero-vega
Newton failure, disabled Newton, invalid/boundary quotes, and the harness's tiny-price rows. For the
`S=100, K=80, T=0.25, sigma=0.1` puts, prices are `1.065447e-6` and `5.989556e-6`, with vegas
`2.663694e-4` and `1.305562e-3`. An exact synthetic price inverts accurately, but adding `1e-6` to it
moves recovered volatility by `0.002750` and `0.000715` respectively. Solver precision does not cure
poor conditioning, quote rounding, or model error. The harness schema and its seven artifacts are unchanged.

### SPX snapshot and observed smile

Reproduce offline, with the existing `plots` extra or dev environment:

```bash
uv run python -m crossprice.surface --snapshot data/SPX_20260910.csv --out docs
uv run pytest tests/test_surface.py -q
```

The input [data/SPX_20260910.csv](data/SPX_20260910.csv) contains 3,946 uncleaned quotes at six
standard SPX AM expiries, 2026-10-16 through 2027-09-17. SPX was chosen because European exercise
matches BSM; SPXW PM contracts are not mixed in. CBOE was chosen for same-payload spot and quotes,
plus its published IV comparator. The snapshot was retrieved 2026-09-10 at 12:42:45 UTC, **before the
regular session**, with spot 7636.3599 last updated 2026-09-09 at 16:14:59 Eastern. Raw payload time
is `2026-09-10 12:42:18` without a timezone. These are not represented as synchronized intraday data.
Valuation uses the spot timestamp as an explicit proxy; actual bid/ask update times are unavailable.

Snapshot schema (one row per source option, prices in index points, rates/IV in annual decimals):

| Fields | Meaning |
|---|---|
| `underlying`, `option_symbol`, `expiry`, `settlement`, `kind`, `strike` | OCC-style symbol, expiry date, AM fixing, call/put, strike decoded in thousandths |
| `expiry_timestamp` | 09:30 America/New_York fixing-time proxy, including DST; actual component openings and payment lag omitted |
| `bid`, `ask`, `bid_size`, `ask_size`, `volume`, `open_interest` | Raw quotes and source counts, including zero/dirty observations |
| `cboe_iv`, `last_trade_price`, `last_trade_time` | Source values unchanged; last price is never a midpoint substitute |
| `spot`, `spot_timestamp`, `valuation_timestamp` | Same-payload spot, raw spot update time, explicit Eastern valuation proxy |
| `snapshot_timestamp_raw`, `retrieved_at`, `source_url` | Raw payload clock, aware UTC acquisition time, public endpoint |

[data/SPX_20260910.json](data/SPX_20260910.json) records source URLs, timestamps, full-payload hashes,
expiry selection and model-input conventions. The accompanying Treasury CSV stores the 2026-09-09
par curve (`date, tenor_years, par_yield_pct`); interpolation and `2*log1p(y/2)` conversion are a
**zero-rate proxy, not a bootstrapped discount curve**. Each expiry's effective forward/dividend yield
comes from the nearest eligible spot-ATM call/put pair and is not a direct dividend forecast.
The external sensitivity uses Multpl's dated 1.06% trailing cash dividend yield as a continuous-yield
proxy. CBOE's unknown model inputs are never fitted to obtain agreement.

Screening retains every input row and records its first rejection reason: finite valid SPX AM quotes,
at least seven days, positive bids/sizes/volume/open interest, uncrossed quotes, relative spread at most
50%, and no duplicate contracts. Per expiry and kind, midpoint monotonicity, vertical-spread bounds and
convexity on the actual unequal strike grid are checked repeatedly. The widest relative-spread quote
in the first violating pair/triple is removed, with symbol tie-breaking. This conservative greedy
screen neither repairs prices nor claims a maximal clean subset or executable arbitrage.

The eight generated artifacts are [docs/surface_run.json](docs/surface_run.json),
[docs/surface_quotes.csv](docs/surface_quotes.csv), [docs/surface_carry.csv](docs/surface_carry.csv),
[docs/surface_sensitivity.csv](docs/surface_sensitivity.csv), and the two `iv_smile` /
`iv_term_structure` PNG/CSV pairs under `docs/figures/`. They record 2,895 exclusions, 13 failed
baseline inversions with reasons, and 1,038 successful inversions. The plotted subset is 670 OTM
quotes with `0.75 <= K/S <= 1.25`; retained ITM inversions are still in the audit. Lines join observed
quotes, not a calibrated or cross-expiry arbitrage-free surface. Bid/ask IV ranges are not confidence
intervals. The run record contains per-expiry ATM/90% observations, source-IV differences and sensitivity
denominators, including alternatives that do not invert. This is input material for the write-up, not a
claim that the single delayed snapshot validates a general market model.

`scripts/fetch_chain.py` is the one-time, standard-library acquisition script, never invoked by tests
or by offline reproduction. It refuses to overwrite existing snapshots. The recorded capture command:

```bash
uv run python scripts/fetch_chain.py --out data \
  --external-dividend-yield 0.0106 --external-dividend-date 2026-09-09 \
  --external-dividend-url https://www.multpl.com/s-p-500-dividend-yield \
  --external-dividend-note "Current yield 1.06%, 4:00 PM EDT Sep 9 2026; trailing 12-month dividend/price, estimated from S&P dividends through June 2026. Used as a continuous-yield proxy, not a forward forecast."
```

Do not rerun acquisition to reproduce these results; use the committed snapshot. Any new capture needs
new source dates and a new output location. The code is MIT-licensed; that license does not extend to
the third-party source data in `data/`, which remains subject to its providers' terms.
